# Selected composition inventory

The user explicitly delegated the choice. These three core-screen comps are references within one design world, selected for field-task clarity and precise programme monitoring. PRODUCT.md and docs/design/RFP_UI_REQUIREMENTS.md own product truth.

| Ingredient | Medium | Implementation commitment |
|---|---|---|
| Forest navigation and meeting/passbook panels | Flutter Material / Container / theme roles | Full-height portal sidebar; strong phone meeting and financial focus, flat colour not generated texture |
| Warm canvas / white content / fine separators | Shared token source and Flutter components | Consistent12–16 radii, clear section rhythm, no nested card stacks |
| Wordmark and person identity | Semantic Text and Material icons / initials | No generated logo or participant photography; no TUIF mark invented |
| Typeface | Bundled Noto Sans / Devanagari regular and semibold | Real600 weight, platform-appropriate type sizes, scalable labels and tabular money |
| Meeting action | Native filled/tonal Material button | Clearly labelled Open meeting, at least56 high, one primary action |
| Passbook | Semantic Flutter layout | Member and confirmed value together; independent pending strip and compact principal row |
| Group comparison and metrics | Flutter table/labelled rows and connected metric band | Actual data, right-aligned amounts; responsive/tablet adaptation |
| Activity/support | Flutter structured rows / empty states | Actual records only, no illustrative history or fabricated category/timestamps |
| Connection/queue states | Shared accessible status components | Icon plus plain language, pending/accepted/failure, concise persistent feedback |
| Illustration/photography | None | Not required by these operating surfaces; no rasterized UI or decorative asset substitute |

The generated passbook's invented date/history and the portal's invented support text/times/principal split are explicitly excluded. Runtime values come from the existing controller/API.
