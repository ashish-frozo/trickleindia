# Non-AWS implementation plan

Baseline: 155aca7. User authorised completing the remaining non-AWS work and proceeding without customer infrastructure or acceptance contacts.

1. Organisation and identity: transactional empty-organisation bootstrap, explicit manager identity mapping, audited provisioning/disable/revoke and last-manager protection; dry-run validated imports with duplicate/reference/financial checks, receipts/reconciliation and safe rollback boundaries. Tests against isolated PostgreSQL.
2. Assistance: grounded help conversation with citations, bounded provider adapter, no financial execution, timeouts/privacy/unsupported-query handling; deterministic local fallback. Voice command navigation and draft-only assistance with explicit microphone consent/availability, no automatic financial confirmation.
3. Client completion: durable profile drafts and language preference, organisation sign-in callback completion, accessible staff administration/reporting surfaces, full content load/retry handling and scope validation.
4. Release/reliability: CI, dependency/secret checks, load/concurrency and restore evidence, local deployment configuration and release/rollback verification; no AWS provisioning.
5. Language/review preparation: import reviewed language packs safely, preserve script tags, validate resources/voice assets, expose no fake translations. Package reviewer tasks and acceptance criteria.
6. Latest native/browser verification and handover: build and exercise current APK where local device facilities permit, refresh screenshots, measure startup, complete reports/manuals/presentation and precise requirement-by-requirement disposition.

Scope baseline: five modules include member profiles, groups/membership/meetings, immutable savings/principal records, enterprise plans/cash records, and Sakhi visits/follow-ups/supervision. Advanced interest/fees/inventory/market/cluster rules are not specified in the RFP and are not to be fabricated as approved requirements. Candidate baseline and acceptance cases must be explicit. Customer-approved BRD, fluent-language review, representative physical-device/TalkBack participation, live provider credentials and formal UAT are external evidence requirements, not tests that can be marked passed locally.

Engineering tasks will receive specification review and then code-quality review. Record actual results and outstanding defects; do not infer full completion from a successful build.
