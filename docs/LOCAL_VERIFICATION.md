# Bounded local release verification

Run from the repository root. No cloud account or service is used. These checks are engineering evidence; translated packs, recorded prompts and production capacity are not accepted by these checks alone.

## Local load probe

Start the existing local PostgreSQL on `127.0.0.1:55432`, then run with a local database owner who can create databases:

```sh
DATABASE_URL=postgresql://ashishdhiman@127.0.0.1:55432/pop_nonaws_load services/api/node_modules/.bin/tsx services/api/src/load-check.ts
```

Change only the database username/password as needed. The script refuses any hostname, port, database, protocol or query parameters outside its hardcoded disposable target. It never connects to `pop_demo` or `pop_test`. It connects to the administrative `postgres` database only to check/create `pop_nonaws_load`; migrations, truncation and seed execute exclusively in `pop_nonaws_load`. **Each run truncates that disposable database's datasets with dependent rows**, preventing accumulating benchmark data. Do not keep real data there. Output defaults to `docs/evidence/nonaws-load.json`; an optional first argument selects another evidence file.

The probe migrates/seeds, inserts 1,000 synthetic member records using the existing member shape, then executes 100 alternating manager bootstrap/dashboard reads with eight workers and 20 identical savings retries with eight workers. Assertions check 1,006 members, exactly one non-replayed result, one ledger record and precisely a 20,000-paise aggregate increase. Errors fail the process. Timing reports p50/p95, JSON body byte totals, workload and machine details. This is Fastify request injection with real PostgreSQL, not network/TLS throughput or production capacity. RSS is sampled Node-process memory, excludes PostgreSQL, and is affected by shared-machine contention. Read bodies include full snapshots; this probe makes no claim that pagination avoids loading the entire dataset internally.

## Reviewed language packs

Candidate scripts remain those in [the script decision](localization/DECISION.md): `or-Orya-IN`, `hoc-Wara-IN`, `sat-Olck-IN`.

```sh
python3 scripts/localization-review.py export --language or --file /tmp/odia-review.csv
# A real language reviewer completes every translation, reviewer and status=reviewed.
python3 scripts/localization-review.py validate --language or --file /tmp/odia-review.csv
python3 scripts/localization-review.py build --language or --file /tmp/odia-review.csv --output /tmp/odia-reviewed-pack
python3 scripts/test-localization-review.py
```

Export retains the existing five CSV columns. Validation requires an exact match to the current English UI and help source keys/text, no duplicates, complete reviewed translations and reviewer identities, and matching substitution arguments/ICU plural types and branch selectors. Build emits `ui_or.arb`, `help.json` and `manifest.json` in a **new** directory; existing directories are rejected. Original assets are untouched and no language is activated. Output includes script-specific locale, canonical source hash, worksheet hash, reviewer identities, generated file hashes and outstanding acceptance gates. Identical source/worksheet input yields identical files; no generation timestamp is included. Source changes require a fresh worksheet review. This is evidence of declared review, not verification of reviewer identity or translation quality. Fonts, rendering at large text, Material localization and participant task testing remain necessary before activation.

## Optional recorded-audio manifest

Place real, permission-reviewed recordings within a pack directory. `audio.json` is supplied by the recording/review team, not generated by this tool. Example schema (values below are descriptive placeholders, not recordings or acceptance evidence):

```json
{"locale":"or-Orya-IN","clips":[{"path":"audio/prompt.wav","mediaType":"audio/wav","sizeBytes":12345,"sha256":"actual-file-sha256","speaker":"speaker identifier","permissionEvidence":"consent record reference","reviewer":"reviewer identifier","reviewEvidence":"listening-review record reference","status":"reviewed"}]}
```

```sh
python3 scripts/localization-review.py validate-audio --language or --file /tmp/odia-reviewed-pack/audio.json --output /tmp/odia-reviewed-pack
```

Checks require existing in-pack local files, no absolute/traversal or escaping symlink paths, unique paths, allowed WAV/MP3/OGG extension/type/signature, exact SHA-256 and byte size, and nonempty speaker, permission and reviewer evidence. This checks package integrity and declared metadata; human listening and consent verification are still required. It does not prove a recording is intelligible, authentic or a translation of its prompt. No clips are fetched, synthesized, or fabricated. Unit tests use explicitly synthetic, temporary silence solely to test file validation and delete it afterward.
